# 片上 YOLO 用实拍数据微调（Claude，2026-10-27 夜 – 10-28）

原来的板上模型 p5_synth 只用合成图训练过。这一轮用板子 CAPTURE 页采集的真实网络输入做微调，再导出 ROM、构建新位流。工程为 `contest_work_v3_advy`：adv03 的完整复制，只换了 YOLO 的三个 ROM 和模型配置模块。

## 1. 数据（`F:/yolo_capture/`，详见 STATUS_FOR_CODEX.md 10-27 晚条目）

- **采集方式**：板子处于 CAPTURE 页，`tools/yolo/board/capture_uart.py` 每 2.4 s 收一帧 128×72，与片上网络的输入完全相同。摄像头朝上对着天花板灯，物体由手持。
- **类别**：0 = 红色收纳盒，1 = 绿色镂空铁框，2 = 蓝色泡沫块。
- **标注**：`tools/yolo/board/autolabel.py` 自动标注，再按拼图逐帧人工复核，错标的帧记入各组的 `drop.json`。
  - `--single`：单物体组。用"与空画面的差"找出剪影，再用颜色种子判断类别。
  - `--multi`：多物体组。红、蓝按颜色取并集；绿色用前景剪影。
  - 有两种蓝框会被丢掉：一是基本落在绿框内的；二是框内蓝色像素占比不到 30% 的，这是灯光透过铁框缝隙形成的。
- **划分**（按组划分，同一组的帧不会同时出现在训练集和验证集）：

| 用途 | 组 | 帧 | 说明 |
|---|---|---|---|
| 训练 | s01, s01b, s02, s03, s04, s05, s05c | 540 | 单物体；蓝+绿；红+蓝；红+绿 |
| 验证 | s06 | 91（150 个框） | 摄像头已被转动，天花板网格变斜；红+绿、蓝+绿 |
| 测试 | 暂时也用 s06 | | **真正的测试集 s07 待采集**（换房间或光照） |

## 2. 训练与结果（`F:/yolo_runs/`，RTX 4060，每次几分钟）

所有数字都按板上 int8 运算，在 s06 的 91 帧上统计。"FPGA 工作点"指板上使用的固定阈值和框数。

| 模型 | 训练 | int8 mAP50（红 / 绿 / 蓝） | FPGA 工作点 精确率 / 召回 |
|---|---|---|---|
| p5_synth（原板上模型） | 只用合成图 | **0.037**（0.07 / 0.00 / 0.04） | 0.16 / 0.11 |
| real01 | 微调 120 轮，lr 1e-3 | 0.738（0.86 / 0.55 / 0.80） | 0.76 / 0.75 |
| **real02（采用）** | 微调 250 轮，lr 2e-3 | **0.836（0.96 / 0.63 / 0.92）** | **0.86 / 0.82**（TP 123，FP 20，GT 150） |
| real03 | 实拍 + 同量合成图混合，150 轮 | 0.723（0.83 / 0.43 / 0.92） | 0.76 / 0.62 |

- **微调设置**：从 p5_synth 出发，anchor 不变，bs 32；用 `--aug` 做增强：上下翻转、±10 像素平移、亮度/对比度/通道抖动，外加原有的左右翻转。
- **对照结论**：只用合成图的模型在真实画面上基本不可用；微调后 mAP50 从 0.04 提高到约 0.84。int8 与浮点只差 0.007，饱和比例 0.03%。
- **绿色最弱（0.63）**：铁框是镂空的，在灯前只剩稀疏的暗线，侧面对镜头时几乎看不见。
- **结果偏乐观的原因**：s06 同时用于挑选训练轮次和三个方案，所以这里的数字偏高。s06 的平台期约为 0.82–0.84。可以写进报告的独立测试精度，要等 s07 测完。

## 6. 上板结果与第二轮（2026-10-28 下午）

- **12:27 advy01 第一次 SRAM 下载**：YOLO 页 85 s 内报告的帧号和延迟一直是 0，没有出框，说明网络一次都没跑完。
  - 为此做了诊断：`yolo_top` 新增参数 `DIAG`（默认 0，行为不变）。DIAG=1 时，报告里的帧号字段换成"阶段 + 层号"，延迟字段换成"推理已用的 ms"。
  - 第一版诊断加了 10 个报告字节，Slice 超出 69 个，构建失败（`cli_advy02`）。精简后的 `cli_advy02b` 能放下（Slice 99.46%，Setup +0.023 ns），位流为 `release/..._advy02diag.bit`，仿真 PASS。
- **15:00 左右板子断电一次，从 Flash 启动 adv03**：YOLO 页正常运行，帧号在前进，延迟 27 ms，能输出框。这说明 YOLO 硬件本身能工作，**而且 adv03 的 YOLO 页这次是第一次在实物上确认**。
- **15:09 advy01 再次 SRAM 下载**：运行正常（延迟 27 ms，有框）。上午"没跑起来"的情况没有复现，原因不明，推测是第一次 JTAG 下载后没有正常启动。**以后如果再出现帧号恒为 0，就断电重启或重新下载，并用 DIAG 版定位。**
  - 用户观察：有框，但"太敏感"，例如头部会被框成蓝色、绿色。
  - 实时记录 387 个报告：81 次 1 个框、5 次 2 个框；绿框和蓝框的置信度多在 0.8–0.9。
- 期间还遇到过 `ftdi_usb_reset failed`：原因是 COM3 读串口的程序和 JTAG 下载同时在跑，以及 USB 插在扩展坞上。改为下载前先关掉串口读取、USB 直插电脑后恢复正常。
- **反例数据 s07neg**（16:00 前后）：拍了头、脸、手、房间画面等，不含目标物体。保留 45 帧，含 10 张空天花板。
