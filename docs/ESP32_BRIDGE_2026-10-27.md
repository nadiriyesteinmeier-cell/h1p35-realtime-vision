# ESP32 免电脑桥接：FPGA 识别结果 → WALL-E（Claude，2026-10-27）

把电脑上的桥接程序（`tools/robot/walle_bridge.py`）移植到 ESP32，使外部控制链路也不需要电脑：

```
FPGA（J1 第 1 脚串口）──杜邦线──> ESP32（RX2）──Wi-Fi WebSocket──> WALL-E
```

## 1. 硬件与组装

接线图：`docs/report/img/esp32_wiring.png`（由 `tools/report/draw_wiring.py` 生成）。

用到的器件：
- ESP32 DevKit V1（ESP-WROOM-32 模组，30 针，CP2102 USB 转串口，Micro-USB）+ 30P 扩展板；
- 本地状态终端，均可选，不接也能正常桥接：
  - 0.96" OLED（I2C）；
  - 红、绿、蓝 LED 各 1 个，以及电阻；
  - 低电平触发蜂鸣器模块；
  - MG90S 舵机；
- 面包板和杜邦线。

套件里其他模块本方案不用：继电器、超声波、步进电机、PIR、摇杆、LCD1602、各类传感器、MAX98357A、数码管。

组装顺序（**全部断电后接线**）：
1. 把 ESP32 插到扩展板上，**丝印逐脚对齐**（EN 对 EN、VIN 对 VIN、3V3 对 3V3）。天线端朝外，USB 口朝扩展板电源接口一侧。
2. 扩展板上的黄色跳线帽：它本身就是连接件，里面有金属片，套住相邻两根针就把它们接通，不需要另外接线。
   - 要求它套住标 “3.3V” 和 “V” 的两根针（用户的板子出厂即如此，2026-10-27 照片确认）。这样所有 V 针都是 3.3 V，OLED 和蜂鸣器的信号不会把 5 V 灌进 ESP32。
   - 不要挪到 “V” 和 “5V” 上。
   - ESP32 的引脚不耐 5 V。
   - 低电平触发蜂鸣器如果接 5 V，会一直响。
3. 按下表接线。扩展板每个 GPIO 一排三针，从外到内是 S（信号）、V（电源）、G（地）。

| 器件 | 器件引脚 | 接到扩展板 | 说明 |
|---|---|---|---|
| FPGA HX1P35A J1 | 第 1 脚（GPIOA_0 = V2） | **D16（RX2）排 S** | FPGA 串口输出，3.3 V，adv03 起与 USB 串口内容相同 |
| FPGA HX1P35A J1 | 第 12 脚（GND） | D16 排 G（或任一 G） | **必须共地** |
| OLED | SDA / SCL | D21 排 S / D22 排 S | I2C，地址 0x3C 或 0x3D 自动识别 |
| OLED | VCC / GND | D21 排 V / D21 排 G | 3.3 V；四个脚的顺序以模块丝印为准 |
| 蜂鸣器模块 | I/O / VCC / GND | D23 排 S / V / G | 低电平触发；VCC 只能接 3.3 V |
| MG90S 舵机 | 橙（信号） | D18 排 S | |
| MG90S 舵机 | 红（+5 V） | 扩展板 **5V** 电源针 | 电源排针在 D13 右边，是一块 2×4 的排针：上排左边两根标 5V，右边两根标 V（3.3 V），下排四根都是 GND。**不能接 V** |
| MG90S 舵机 | 棕（GND） | D18 排 G | |
| 红 LED | 长脚 ← 220 Ω ← | D25 排 S | 短脚接面包板负极排 |
| 绿 LED | 长脚 ← 100 Ω ← | D26 排 S | 同上 |
| 蓝 LED | 长脚 ← 100 Ω ← | D27 排 S | 同上 |
| 面包板负极排 | | 任一 G | |

  - J1 引脚依据：`HX1P35A开发板引脚分配汇总.pdf`（四、40 芯 GPIO 扩展口 J1）。
  - **J1 实物位置（2026-10-27 用数据确认）**：J1 是板子左边那条框式排针。网口、红色电源键朝上放时：
    - **第 1 脚在远离网口那一端**（靠板上“安路科技”Logo、红色开关的对侧）**的第一排、靠 FPGA 芯片的里侧那列**；奇数脚都在里侧列，偶数脚都在外侧列（靠板边）。
    - 地线可以用第 12 脚或第 30 脚，都在外侧列，正对面的里侧针是电源：
      - 第 12 脚：从 Logo 端数第 6 个；正对面是第 11 脚（5V）。
      - 第 30 脚：从网口端数第 6 个；正对面是第 29 脚（3.3V）。
    - 网口那端塑料框内的白色标记不是第 1 脚标记。
    - 用户的描述和照片有过不一致，最终以数据和照片为准：棕线在 Logo 端里侧时 ESP32 收到 5 行/s。
    - 杜邦头要压到框底。
  - 电阻色环（5 环金属膜）：220 Ω 为 红红黑黑棕，100 Ω 为 棕黑黑黑棕。
  - 绿灯、蓝灯的正向压降约 3 V，所以用 100 Ω，否则太暗。
4. 供电：只用 ESP32 小板自己的 Micro-USB，就是 BOOT 和 EN 两个小按键中间、紧挨 CP2102 芯片的那个口（接电脑或手机充电器）。
   - 扩展板上的 DC 圆口（6.5–12 V）、它自己的 Micro-USB 和 Type-C 只能供电，不能烧录，本方案不用。
   - **FPGA 的 5V 不要接到 ESP32**，舵机电流可能拖垮 FPGA 板的电源。
   - 扩展板自己的 USB-C 或 DC 口不要和 ESP32 的 USB 同时接。
   - 舵机一动 ESP32 就重启或断网：换 2 A 充电器，或减小舵机负载。
5. 舵机装上单臂舵盘，可以贴一个纸箭头，上电后会转到 90°（正中）。

工作时：
- 板载蓝灯（GPIO2）：
  - 快闪：设置模式；
  - 慢闪：在连 Wi-Fi、找瓦力或等 FPGA 数据；
  - 常亮：已连上瓦力，并且正在收到 FPGA 报文。
- 本地状态终端：
  - 三色灯：报文中该颜色存在，且面积 ≥ 最小面积，就点亮。
  - 蜂鸣器：新颜色出现时响 1 声，越线时响 3 声。设置页可以关掉。
  - 舵机：指向主导颜色的 x 位置，范围 30°–150°，最快 125°/s。目标消失后回到 90°。方向可在设置页反转。
  - OLED 共 8 行：
    1. 模式和瓦力连接状态；
    2. IP；
    3. FPGA 报文速率、CAM/DSP 帧率；
    4–6. 红、绿、蓝各一行，显示形状、X 和面积，“>” 标出主导颜色；
    7. 最近事件；
    8. 最近发给瓦力的命令。
  - 没连上瓦力（或在设置模式）时，本地终端照常工作，可单独演示。

## 2. 固件

- 源码：`esp32/walle_esp32_bridge/walle_esp32_bridge.ino`（Arduino-ESP32 3.3.12，不依赖第三方库）。
  - OLED 驱动是自写的：SSD1306/SSD1315 页寻址，5×7 字库，已渲染成图片核对过字形。
  - 舵机和蜂鸣器用 LEDC 通道 0 和 2，占用不同的定时器（50 Hz / 2.7 kHz）。
- 编译与烧录：使用 E 盘 Arduino IDE 自带的 arduino-cli，配置文件 `F:/arduino/arduino-cli.yaml`；数据和下载目录都在 F 盘，并配置了代理。
  ```
  arduino-cli --config-file F:/arduino/arduino-cli.yaml compile --fqbn esp32:esp32:esp32 --build-path F:/arduino/build/walle_esp32_bridge F:/fpga_s2/esp32/walle_esp32_bridge
  arduino-cli --config-file F:/arduino/arduino-cli.yaml upload  --fqbn esp32:esp32:esp32 --input-dir F:/arduino/build/walle_esp32_bridge -p COMx F:/fpga_s2/esp32/walle_esp32_bridge
  ```
- 功能：
  - 解析 FPGA 报文，格式与 `robot_rules.py` 相同；规则也照搬，包括主导颜色（1.5 倍面积、连续 2 行）、左中右分界 520/760 加回差 30、越线、连续 10 行无目标判消失、同类事件间隔 1.5 s。
  - 两套规则：手势（rules.json）和移动（rules_drive.json，绿行、红停、蓝退、左右转）。
  - 动作排队（一次一条，等机器人回复“完成”或 8 s 超时，只保留最新的一条）；眼灯命令立即发送；急停立即发送。
  - 连接瓦力：先按设置的 IP，空则用 mDNS 找 `wali.local`；断线后按 1–15 s 退避重连；每 1.5 s 发一次心跳。
- 按键：
  - BOOT 短按：手势 ↔ 移动，掉电保存。切出移动模式时先发急停。
  - BOOT 运行中长按 3 s：清除 Wi-Fi 设置并重启，进入设置模式。
  - BOOT 是芯片的启动引脚，**上电时不要按住**，否则会进入下载模式。

## 3. 设置（Wi-Fi 密码不写进源码）

1. 第一次上电（或长按 BOOT 3 s 后），ESP32 开启热点 **WALLE-BRIDGE**，密码 `walle1234`。
2. 手机连上这个热点，浏览器打开 **http://192.168.4.1**，填写：
   - Wi-Fi 名称和密码：**与瓦力连接的是同一个网络**；
   - 瓦力 IP：可留空，留空则自动查找 `wali.local`；
   - 最小目标面积：默认 4000；
   - 规则：手势或移动；
   - 蜂鸣器：开或关；
   - 指示舵机方向：正向或反向。
3. 点“保存并重启”，ESP32 会连上该 Wi-Fi 并开始工作。设置保存在 ESP32 的 NVS 中，断电不丢。

网络方案：
- **完全不用电脑**：用一部手机开热点，瓦力和 ESP32 都连这个热点。瓦力需要用它自己的配网方式切换到这个热点，由用户操作。
- 仍用电脑的移动热点：电脑只当 Wi-Fi 热点，不再运行桥接程序。
- 有些手机热点不转发组播，这时 mDNS 找不到瓦力，在设置页填写瓦力 IP 即可。

  - 之后把红线这一端改接到 ESP32 电源排针的 GND。
- 2026-10-27 晚 **端到端（手势规则）通过，全程不经电脑桥接**。

## 5. 2026-10-28 晚：YOLO 页也能驱动瓦力，瓦力查找更可靠

- **固件解析 YOLO 报告**：FPGA 在 YOLO 页、CV+YOLO 页（yolo_top 模式 1、2）每 200 ms 发一份 YOLO 报告，格式为 `Y n 帧号 延迟`，后跟 n 行框。
  - 一份完整报告换算成和传统报告相同的 Det[3]：每类取得分最高的框，x 取框中心，面积取框的面积。
  - 规则、动作与原来相同。YOLO 没有越线计数，所以 YOLO 页不发越线事件。
  - 串口状态行和 OLED 第 3 行标出数据来源是 yolo 还是传统识别。
  - CAPTURE 页发的是二进制图像，ESP32 不识别，正常忽略。
- **侧向防抖**：
  - 现象：YOLO 框中心在左/中/右分界附近来回跳，瓦力不停举手；颜色动作排在队列里，还被举手顶替掉。
  - 修改：
    1. 新的一侧要连续出现 2 份报告（SIDE_N）才算数；
    2. YOLO 来源时，回差加倍（60 像素）；
    3. 目标出现后 2.5 s（APPEAR_HOLD）内不触发举手。
- **找瓦力**：瓦力的 IP 从 .192 变成了 .135，mDNS 又刚好失效。
  - 查找顺序改为：设置页里填的 IP → 上次连通的 IP（NVS `lastip`）→ mDNS → 扫描本网段，看哪个地址的网页里有 “WALI”。
  - 连上后记住该 IP。
- **实测**（用户，FPGA 运行 Flash 里的 advy03，停在 YOLO 页）：
  - 第一版：三色眼灯都对，绿色点头；但总在摆手，红色的挥手有时被顶替。
  - 防抖版（日志 e2e_yolo2）：
    - 红 → 眼红 + 挥手；
    - 绿 → 眼绿 + 点头；
    - 蓝 → 眼蓝 + 呼吸灯；
    - 物体真正移到一侧时只举一次手；
    - 拿走后恢复平静。
  - 用户确认“都正确了”。
- **结论**：除 CAPTURE 页外，其余 6 个页面都能驱动瓦力。
  - CV、WB、MOTION、HIST EQ 页由传统颜色识别驱动；
  - YOLO、CV+YOLO 页由 YOLO 检测网络驱动。

## 6. 2026-10-29：蓝色加双臂动作

- 现象：用户在 YOLO 页试蓝色，觉得“没反应”。
  - 日志显示 6 次蓝色出现都发出了“眼蓝 + 闪烁”，瓦力也都回复了 ok。
  - 问题在于没有肢体动作，不容易看出来。
- 修改：蓝色出现时再发 `self.wali.servo` 左右臂 60°，1.8 s 后（ARMS_UP_MS）由 pollQueue 发左右臂 120°。
  - 舵机命令立即回复，不进动作队列。
- 用户确认“蓝色有效果”。
- 用户决定 YOLO 保持“三类颜色目标”，不再追求只识别三个特定物体：红色、绿色图片也会被识别，这一点接受。

## 7. 2026-10-31：接入本地状态终端（OLED、三色灯），取消舵机

用户接上了 OLED（I2C 地址 0x3C）、红绿蓝三色灯和 MG90S 舵机。

- **舵机**：
  - 现象：ESP32 由笔记本 USB 供电，开机即陷入欠压复位循环（25 s 内 Brownout 10 次）。
  - 固件改为开机 6 s 后才给舵机 PWM（SERVO_START_MS），Wi-Fi 发射功率降到 13 dBm，开机循环消失。
  - 但舵机一开始转，约 1 s 后 ESP32 仍会欠压复位或死机：出现过 Guru Meditation，引导程序读 Flash 校验失败，说明电源电压跌落。
  - 用户决定**取消舵机**。固件保留舵机代码，不接舵机时无影响。
  - 以后若要用舵机，必须单独 5V 供电，或改用 2A 充电器。
- **三色灯**：
  - 一开始没有串电阻。固件把 GPIO25/26/27 设为最弱驱动（GPIO_DRIVE_CAP_0）先限流，之后用户补上了电阻。
- **找机器人**：
  - 机器人地址变为 192.168.137.232。
  - 网段扫描改为从本机地址向两边扫，每个地址连接超时 150 ms，读页面最长 1.5 s，全网段扫描最多每分钟一次。
  - 连上后把地址记入 NVS（lastip），下次开机约 2 s 直连。
  - ESP32 反复复位后，机器人会暂时拒绝 WebSocket（旧连接未释放），约半分钟后恢复。
  - 连不上时，串口和 OLED 的事件行会区分 ROBOT NOT FOUND（没找到）和 ROBOT REFUSED（拒绝连接）。
- **实测**（用户，YOLO 页）：
  - OLED 各行显示正确，三色灯随颜色点亮，瓦力动作正确。
  - 5 分钟内无复位：出现 3 次识别事件，0 次复位。
