## 2. 操作（板上）

| 器件 | 功能 |
|---|---|
| SW1 | 上 = 处理后画面；**下 = 基线原画面（旁路）** |
| SW2 / SW3 | 显示模式 `{SW3,SW2}`，两页（见下）；MODE 条（原 v1 文字块第 2 行位置）显示当前名称 |
| SW4 | 上 = 画图形：竖直计数线（x=640，可调）；识别模式开启时同时画三色目标框和十字 |
| KEY1（松开时生效） | 识别模式开 / 关：开 = 三色框 + 识别面板；关 = v1 的单目标画面（红色目标、绿色框） |
| KEY2（短按，松开时生效） | 自适应阈值开 / 关（OSD 面板第一行 `THR:ADAPT` / `THR:FIXED`） |
| KEY2（按住 ≥ 1 s） | 切换显示页：页 0 分析视图，页 1 风格视图（松开后不再切换阈值） |
| KEY1 + KEY2 同时按 | 清零三个越线计数器（两个键松开时都不会触发各自的切换） |
| KEY3 / KEY4 | 计数线向左 / 右移 16 像素（按住约 0.4 s 后连续移动，范围 32..1247） |
| LED1..4 | 找到任一目标 / 适配器几何错误（LED2 应常灭）/ 约 1.9 Hz 心跳（LED3 每 16 帧翻转，表示统计在逐帧更新）/ 处理路径启用 |
| 数码管（SW6 拨**上**） | 左四位 = 三个目标的越线总数（最大 9999），第五位 `F`，后三位 = 实测相机帧率；SW6 拨下时同样的 16 个引脚驱动双色 LED，会乱闪，属板上复用 |
| 蜂鸣器（SW5 拨**下**接通） | 每次计到一次越线响约 0.15 s（2 kHz 方波）；低电平响，空闲高电平 |
| 串口（USB-UART，COM 口，115200 8N1，只发送） | 每 0.2 s 一行，格式见第 5 节 |

## 3. 数据通路与模块

```
uivtc de/user/last + 帧缓存 RGB ─► video_pos_adapter ─┬─► rgb_to_gray ─► edge_style (Sobel, 2 行缓存) ─┐
                                                       │          └─► luma_mean ─► thr_adapt              ├─► view_mux_style ─► osd_overlay ─► osd_ext ─► hdmi_tx
                                                       ├─► color_seg_rt ×3 (红 / 绿 / 蓝，通道置换，运行时阈值) ─► hit_open ×3 (去噪) ─► 命中标志 ─┘
                                                       │                                              └─► frame_bbox ×3 ─► shape_classify ×3 / cross_counter ×3
                                       骨干外围：ui_ctrl（按键）、fps_meter + byte_cdc（帧率）、uart_report、seg7_scan、beep_ctrl
```

| 模块 | 作用 | 固定延迟（拍） |
|---|---|---|
| `contest_vision_v2` | 顶层集成，旁路，LED，外部接口 | `uivtc de` → `tx_de`：`SKEW`+15 = 17（旁路 3） |
| `color_seg_rt` | 每色一个：运行时阈值、固定 / 比例两种判据 | 2 |
| `hit_open` | 每色一个：去掉一行内短于 5 个像素的命中段（1-D 开运算），孤立噪点不再拉大包围框 / 抖动中心；长度 ≥ 5 的目标边缘不变 | 5 |
| `luma_mean` + `thr_adapt` | 稀疏网格（40×45 个点）平均亮度，帧末串行除法；亮度映射成红色下限 `32 + mean/2` | 一帧后可用 |
| `shape_classify` | 填充率 `count / (w·h)` 与宽高比分类 | 3 |
| `cross_counter` | 越线状态机（死区 12 px、连续 2 帧确认、丢失 5 帧遗忘），每色一个 | 1（相对 `frame_done`） |
| `edge_style` | Sobel `\|Gx\|+\|Gy\|`，两个 2048×8 行缓存（块 RAM） | 3（边缘图相对流位置偏 1 像素 + 1 行） |
| `view_mux_style` | 8 种显示 | 1 |
| `osd_ext` | 三色框 + 十字 + 识别面板 + MODE 条 | 3 |
| `ui_ctrl` / `key_debounce` | 按键：去抖、释放时切换、长按、组合键、连发 | — |
| `fps_meter`、`pulse_to_toggle`、`byte_cdc` | 50 MHz 晶振时基，相机帧起始 / 显示 vsync 计数，翻转同步 + 双采样读回 | — |
| `uart_report`、`seg7_scan`、`beep_ctrl` | 串口一行文本、数码管动态扫描、蜂鸣 | — |

阈值与规则（运行时可切换）：

- **固定**：`R ≥ 80 且 R ≥ G+30 且 R ≥ B+30`（绿、蓝通过通道置换用同一模块）。
- **自适应**：`8R ≥ 13G 且 8R ≥ 13B`（G、B 不超过 R 的 61.5%）且 `R ≥ 32 + mean/2`，颜色判据未改。针对真实画面边缘不明显，风格修正版把边缘阈值改为 `20 + mean/2`，固定模式默认 50，可通过 `EDGE_FIXED_THR` 调整；降低阈值可能增加噪声边缘，实际效果待复测。
- **去噪**：每个颜色的命中流先过 `hit_open`（`OPEN_RUN` = 5）：一行里连续命中不足 5 个像素的段被删掉，所以单个噪点、细竖线都不会进入统计；代价是目标尖角（例如三角形顶端宽度小于 5 的几行）被削掉，包围框和面积相应略小（仿真里三角形少 12 个像素、顶端 4 行）。统计和彩色显示（MASK / TINT）都用去噪后的结果。
- **形状**：填充率 ≥ 0.875 → RECT；0.69–0.875 → CIRC（宽高比 3/4..4/3）否则 OVAL；0.375–0.625 → TRIA（三角 / 菱形）；其它 → OBJ。适合正对镜头、颜色干净的彩纸剪贴；倾斜、遮挡、分割空洞会降低填充率。
- **越线**：每帧取目标包围框中心 x，相对竖线分成左 / 右 / 死区（±12 px）；连续两帧明确在另一侧才计一次；目标丢失超过 5 帧再出现只重新学习一侧；一个颜色一个目标。

## 4. 外部引脚（v2 在 v1 的 `I_sw` / `O_led` 之外新增，来自《HX1P35A 开发板手册》和引脚汇总，原理图已核对 UART 方向）

| 信号 | 引脚 | 说明 |
|---|---|---|
| `I_key[0..3]` | D5, A9, B9, C7 | KEY1..4，低 = 按下，内部上拉 |
| `O_buzzer` | C12 | 低 = 响（经三极管；SW5 断开 / 接通蜂鸣器） |
| `O_uart_tx` | H1 | FPGA 发送 → USB 转 UART 芯片（`TXD`）；原理图中 BDBUS1 ↔ FPGA_TXD；RXD（J1）本版不用 |
| `O_seg[0..7]` | C9, C11, B11, E7, E6, B6, B7, E5 | 段 a b c d e f g h，**低电平点亮**（共阳） |
| `O_sel[0..7]` | G15, G14, A17, A18, B16, A15, B15, A14 | FPGA 位选引脚低电平有效（PNP9012 驱动），`O_sel[0]` 是最左边的数码管；原 v2d 误用高有效，修正版见上板记录 |

约束 `pin.adc` 追加 22 行；`camera_to_dsi_display.sdc` 追加两条 `set_false_path`（`HDMI_PIXEL_CLK` ↔ `sys_clk_50m`）：帧率计只通过翻转同步器 / 双采样跨这两个时钟，基线本身在这两个时钟之间没有任何路径（基线和 v2 的时序报告里的路径组对比可核对），异常只影响新增的跨时钟路径；不加时 TD 会把它当成带偏斜的同步路径，报一条 -0.836 ns 的保持违例（第 7 节的第一次构建 `cli_v2a` 就是这样）。相机帧起始来自 MIPI 字节时钟域的 `S_ISP_O_tuser`，SDC 已把该域与其它域设为异步。

## 5. 串口输出格式（115200 8N1，每 0.2 s 一行，115 个字符 + CR LF）

```
R:RECT,X0549,Y0329,A003600,N00000;G:CIRC,X0640,Y0450,A002821,N00000;B:TRIA,X0929,Y0429,A001860,N00000;CAM060,DSP060
```
每个颜色块：颜色字母、形状（RECT/CIRC/TRIA/OVAL/OBJ 或 ----）、中心 X、Y（无目标时为 ----）、命中像素数 A、越线计数 N；最后是实测相机帧率与显示刷新率。波特率分频 651（75 MHz 时钟 → 115,207 baud）；若实际像素时钟不是 75 MHz，波特率会有相应偏差（75 → 74.25 MHz 约 −1%，串口仍可用）。

## 7. 实际验证结果与未验证项

**仿真（ModelSim SE-64 2020.4，真实 `uivtc.v` 1280×720 时序，20 帧，约 5–9 分钟，25,947,496 拍）：整机测试 `tb_custom/tb_vision_v2.v` PASS，0 错误**（日志 `logs_custom/modelsim_vision_v2e.log`）。场景是合成的"彩纸"：灰底，红色 60×60 矩形（在计数线左右来回），绿色圆盘（圆心在线上），蓝色三角形。检查内容：

- 三个目标的像素数、包围框、中心、形状类别与测试台里独立逐像素算出的期望值**完全一致**（含 `hit_open` 去噪后圆盘少 2 个像素、三角形少 12 个像素 / 顶端 4 行的预期）；
- 越线计数：红色 2 次（右、左各一次，确认需连续两帧），绿色（圆心在死区）0 次，蓝色 0 次；蜂鸣器响了；数码管解码为 `0002` 和 `F`；
- 实测帧率计（相机帧起始与显示 vsync 来自两个不同的时钟域）读出在预期范围内；
- 串口一行文本的前 102 个字符与期望字符串逐字符一致（`R:RECT,X0549,Y0329,A003600,N00000;G:CIRC,X0640,Y0450,A002819,N00000;B:TRIA,X0929,Y0431,A001848,N00000;`）；
- 按键：KEY1 切识别模式、KEY2 短按切自适应、KEY2 长按切显示页（且松开不再切阈值）、KEY1+KEY2 清零计数（模式不变）、KEY4 单击 +16、KEY3 按住连发；
- OSD：识别模式下 461 个关键像素（红 / 绿 / 蓝框、十字、计数线、背景、目标内部）逐个检查颜色，识别面板各行字形颜色的像素数、MODE 条（白字 + 不透明深色底）；
- 暗光（30%）+ 固定阈值：三个目标都找不到；打开自适应后（上一帧平均亮度 18 → 红色下限 41）三个目标都找到；恢复正常光后仍找到；
- 显示模式：MASK 视图在目标边界像素处的颜色（检查去噪后的命中流与画面对齐）、SKETCH / CARTOON / EDGE+ / THERMAL 的指定像素颜色，边缘像素数（红色矩形周围 235 个）；
- 每一拍：`tx_de` / `tx_vs` 等于 `uivtc` 输出延迟 `SKEW`+15 = 17 拍；旁路帧 `tx_*` 逐拍等于基线信号；`led` 检查。
