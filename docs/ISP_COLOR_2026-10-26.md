# ISP 色彩级：黑电平 + 镜头阴影校正 + 白平衡/曝光闭环（Claude，2026-10-26）

> 状态：RTL、逐位参考模型、仿真、变异测试已完成；TD 构建与上板见文末。不要把仿真结果当成实物画质。

## 1. 为什么做（实测依据）

2026-10-26 wb02 上板，诊断视图白纸平场 + 暗场（`docs/IMAGE_SHADING_2026-10-16.md` §6）：

- 黑电平没扣：暗场 R/G/B ≈ 17.8 / 18.6 / 17.4（8 位），全画面均匀。白平衡增益（R×1.25、B×1.49）把这个底乘上去，暗处就变成紫蓝色；照片里 CV 页把紫色背景误判成红色目标（`TARGET:FOUND AREA:379747`）。
- 镜头颜色阴影：扣黑后 R/G 从中心 0.610 到角 0.749（+23%），B/G 从 0.516 到 0.617（+20%），以光轴为中心径向分布；亮度角/中心 0.666。这就是“中间绿、四周红（品红）”。
- 曝光偏低：白纸扣黑后中心 G 只有约 46/255。

## 2. 做了什么

新模块 `rtl_custom/isp_color.v` 取代 ISP 链里的 `awb_frame.v`（接口、模式码、增益读回都相同，wb_ctrl / wb_osd / shade_diag 不用改）。每个像素、每个通道：

```
out = min(255, (eff * max(0, in - BLK)) >> 12)      eff = min(65535, (gain * lsc(x, y)) >> 10)
```

| 部分 | 做法 |
|---|---|
| 黑电平 | BLK = 18 / 19 / 17（暗场实测取整），在乘增益之前减，负数截到 0 |
| 镜头阴影 LSC | 表 `lsc_rom.v`：21×13 个节点（x = 64i, y = 64j），每节点 R/G/B 三个 Q2.10 增益，1 块 ERAM。由 `tools/shade/gen_lsc_table.py` 对今天的白纸数据（扣黑）按通道拟合 4 次二维多项式（残差 RMS < 1%），增益 = 中心值 / 该处值（中心 1.0，角最大约 1.67）。垂直方向每行按节点插值（ROM 两行 + 13×6 位小乘法，3 拍/节点，行间空闲时取每行前三个节点、行内每 16 拍取下一个），水平方向每拍增量累加（全部是移位，没有除法） |
| 合并乘法 | 每拍（4 像素）一次 gain × lsc（3 个 DSP），原有的每像素乘法器不变；G 仍用移位相加 |
| 白平衡 + 曝光 | 统计输出端（已扣黑、已校正）每拍第一个像素的 R/G/B 和；帧后 est = gain × 110 × 230400 / sum（三通道均值都拉到 110 = 灰度世界 + 曝光），auto = (gain + est + 1) / 2（半步，稳定）。增益范围 0.25–4.00。帧后顺序计算约 250 个时钟 |
| 模式 | AUTO：扣黑 + LSC + 闭环增益；MAN：扣黑 + LSC + 手动增益（WB 页）；OFF：**完全原始**（不扣黑、不校正、增益 1.0），用来现场对比和测平场。所有切换都在帧首 |
| 显示路径 | colour4 静态校色（R×1.25 等）关闭（`u_image_balance.enable = 0`）；提亮/饱和度仍按拨码 |

延迟：数据比输入晚 DELAY + 3 = 27 个时钟（原 awb_frame 为 26），O_tuser 仍是输入 tuser（厂商 video_in 的约定）。行间至少要 10 个空闲时钟（实际相机约 1000）。

WB 页显示的 AUTO 增益现在包含曝光（例如 R2.1 G1.6 B2.4），一键 MAN 接管的也是这个值。

## 6. 局限

- LSC 表来自一次白纸测量（这颗镜头、这块板）。换镜头或换板要重测并重新生成表、重新构建；片上一键标定还没做。
- 曝光是数字增益（最大 4×），传感器的曝光时间没改；暗场景会有更明显的噪声。
- 没有 gamma；目标均值 110 是线性值。

## 7. 实物问题：暗场景整片发绿（isp02），修正为 isp03

- 现象（2026-10-26 用户照片）：CV 页和 WB 页 AUTO 整片发绿、有颗粒；WB 页读数 `WB AUTO R4.00 G4.00 B4.00`、窗平均 `R128 G209 B103`。白纸平场时没有出现。
- 原因（设计缺陷）：isp02 的闭环把白平衡和曝光放在同一组增益里，并且**每个通道单独截到上限 4.0**。场景暗（人、深色衣服）时曝光要求超过 4 倍，三个通道都被截到 4.0、彼此相等，白平衡失效，露出传感器本身的颜色（扣黑后 R/G≈0.6、B/G≈0.5，即绿强）。颗粒是 4 倍数字增益放大的噪声。白纸亮，增益没碰到上限，所以平场测量正常（但 B 已被截住，B/G 0.92）。
- 修正（isp03）：
  1. 两遍计算：先算每通道未截断的估计 er_c（上限 16 倍），如果最大的 er 超过 GAIN_MAX，三个通道按同一比例 GAIN_MAX / max(er) 缩小——红绿蓝比例保持，太暗的场景只会偏暗、不会偏色。
  2. GAIN_MAX 从 4.0 提到 8.0（B 通道本身需要约 1.9 倍于 G 的增益）。
  3. WB 页手动范围 0.25–8.00（`wb_ctrl` H_MAX 800）；百分数→Q4.12 换算改为 `(h × 1342177 + 16384) >> 15`，对 h ≤ 1023 逐值精确（原公式从 h = 537 起有误差），逐位移位相加、约 36 个时钟算完三路，不占 DSP。
- 验证：参考模型与测试台增加 4 个暗帧（R 最暗、B 最暗、G 最暗各一帧触发限幅），11 帧逐位比较；`tb_wb_ctrl` 扫过 0.25–8.00 全部 776 个值；wb_ctrl 变异 35/35。
- 仍然存在：暗场景下数字增益放大噪声；根本办法是提高传感器曝光（I2C 写曝光/模拟增益寄存器），需对照 `D:/SC500CS_数据手册_V1.8.pdf` 设计，尚未做。

## 8. isp03 暗场景仍偏绿，修正为 isp04；实物反馈

- isp03 的现象：暗场景 CV 页仍偏绿（WB 页读数 R5.59 G3.54 B7.10，窗平均中性 R152 G156 B152）。
- 原因：统计里混入了接近黑电平的像素和饱和像素，加上显示路径饱和度 ×2 与额外暗部提升叠加，色差被放大约 4 倍。
- 修正（isp04）：
  1. 统计只用有效像素：输入 G ≥ 黑电平 + 4，且三通道都 < 250。
  2. 有效像素少于 1% 时保持原增益。
  3. 饱和度从 ×2 降到 ×1.25，去掉额外暗部提升。
- 实物（2026-10-26 用户）：CV 页发绿基本解决，画面基本正常；转到一些刁钻角度时仍偶尔发绿。
  - 推测原因：灰度世界白平衡的固有偏差。单一颜色占满画面时，算法会把它往灰拉，看起来就偏向补色。
  - 未取数据。下一次出现时，在 WB 页读 AUTO 增益和窗平均，再决定是否改为“只统计接近中性的像素”，或把 R/G、B/G 增益比限制在白点附近。
- 变异测试：isp04 版 33/34。幸存的 m19 是去掉 est ≥ GAIN_MIN 下限，属于测试缺口。
  - 补了第 13 帧：R 在黑电平（sum = 0 → er = 65535），B 原始值 238..245 且有效，手动 1.0；est_B 936 被下限抬到 1024。
  - 补了第 14 帧：自动模式。
  - 测试帧数 NFR 13 → 15。
